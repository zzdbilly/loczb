<h2>TIOBE 前十：Rust 用十一年证明了什么</h2>
<p>2026 年 7 月，TIOBE 指数迎来 25 周年，Rust 首次闯入前十。</p>

<p>关键变化是：<strong>越来越多的人在工作中使用 Rust</strong>，而非仅仅是兴趣探索。这代表行业正在主动拥抱 Rust。</p>

<ol>

<p>CLI 工具和 WASM 的高增速值得特别关注。它们说明 Rust 正在从「底层基础设施语言」扩展到更广阔的工具生态。</p>
<h2>为什么是现在</h2>
<p>在 TIOBE 二十五年的历史中，从来没有一个语言像 Rust 这样，以「安全」作为核心竞争力进入前十。</p>
<h3>安全优先的时代</h3>
<p>过去三年的供应链安全事件把「内存安全」这个话题从开发者的技术讨论提升到了政策层面：</p>
<ul>
<li>美国 CISA 的「Memory Safety Roadmap」明确建议关键基础设施项目迁移到内存安全语言</li>
<li>欧盟的 Cyber Resilience Act 对 C/C++ 项目的合规性要求大幅提高</li>
<li>Google 在 Android 和 Chrome 中持续推进 Rust 替换，2026 年 Android 平台已累计引入超过 500 万行 Rust 代码</li>
</ul>
<p><strong>安全已经不再是可选特性，而是合规要求。</strong> 这个趋势对 Rust 比任何其他语言都更有利。</p>
<h3>基础设施的不可逆迁移</h3>
<p>过去几年，一批重量级项目用 Rust 重写了核心组件：</p>
<pre><code class="language-bash"># 2026 年的基础设施栈
- Linux 内核：30+ 个 Rust 模块
- Android：500 万+ 行 Rust 代码
- Cloudflare Pingora：替代 Nginx
- Discord：Go → Rust 重写关键路径
- Firefox：CSS 引擎 Servo（Rust）
- Google：Chrome 中的 QUIC 实现
</code></pre>
<p>这些迁移一旦完成，就没有回头路了。它们为 Rust 提供了稳定的「基座」用户群。</p>
<h2>语言本体的进化</h2>
<p>2026 年的 Rust 语言本身已经和 2023 年大不相同。</p>
<h3>trait 和异步的成熟</h3>
<p>Rust 2024 Edition 带来的改进完全落地。最大的变化是异步生态：</p>
<pre><code class="language-rust">// 2026：trait 原生支持异步
trait DataProcessor {
    async fn process(&amp;self, input: &amp;[u8]) -&gt; Result&lt;Vec&lt;u8&gt;, Error&gt;;
    async fn stream(&amp;self) -&gt; impl AsyncIterator&lt;Item = Vec&lt;u8&gt;&gt;;
}
</code></pre>
<p>不再需要 <code>#[async_trait]</code> 外部 crate，编译器原生支持异步 trait 方法。<code>AsyncIterator</code> trait 也已稳定，异步流处理变得和同步迭代一样自然。</p>
<p><code>impl Trait</code> 在返回值位置的能力增强：</p>
<pre><code class="language-rust">// 2026：返回复杂泛型类型不再需要 Box
fn build_pipeline() -&gt; impl Pipeline&lt;Input = String, Output = Result&lt;Vec&lt;u8&gt;, Error&gt;&gt; + Send + Sync {
    Compose::new()
        .add(ParseStage::new())
        .add(TransformStage::new())
        .add(EncodeStage::new())
}
</code></pre>
<h3>特化的有限落地</h3>
<p>RFC 3623 在标准库内部启用了有限特化。用户层面最直观的感受是：<code>Vec::sort</code> 现在能根据元素类型自动选择最优排序算法。</p>
<pre><code class="language-rust">let mut numbers = vec![3, 1, 4, 1, 5, 9, 2, 6];
numbers.sort(); // 对于整数，自动使用基数排序
</code></pre>
<p>这在性能敏感场景下能节省约 30% 的排序时间。</p>
<h3>编译速度的改善</h3>
<p>编译速度一直 Rust 的痛点。2026 年的改善是实质性的：</p>
<pre><code class="language-toml"># Cargo.toml：2026 年的编译器优化选项
[profile.release]
lto = &quot;thin&quot;    # thin LTO 现在是默认推荐
codegen-units = 16
pgo = true      # 原生 PGO 支持
</code></pre>
<ul>
<li>并行前端：解析和类型检查可以多线程执行</li>
<li>增量编译：跟踪文件粒度依赖变化</li>
<li>LTO 改进：thin LTO 在 <code>-O2</code> 下比 2024 年快 2 倍</li>
</ul>
<p>测试数据：一个 50 个 crate、8 万行代码的中型项目，clean build 从 2024 年的约 6 分钟降到了约 3 分钟。</p>
<h2>生态系统的扩张</h2>
<p>语言的进化只是故事的一半，生态的成熟才是 Rust 进入前十的真正原因。</p>
<h3>异步运行时</h3>
<p>tokio 以约 85% 的市场份额形成绝对垄断。但多元化的尝试也有成功：</p>
<ul>
<li><strong>tokio</strong>：异步 I/O 的主流选择</li>
<li><strong>smol</strong>：在嵌入式领域崛起，适合无 alloc 场景</li>
<li><strong>glommio</strong>：基于 io_uring 的高性能运行时</li>
</ul>
<p>tower 中间件栈已经成为 Rust 异步网络的事实标准：</p>
<pre><code class="language-rust">use tower::{ServiceBuilder, ServiceExt};
use tower_http::{
    cors::CorsLayer,
    trace::TraceLayer,
    compression::CompressionLayer,
};

let service = ServiceBuilder::new()
    .layer(TraceLayer::new_for_http())
    .layer(CorsLayer::permissive())
    .layer(CompressionLayer::new())
    .service(handle_request);
</code></pre>

<p>axum 在 2026 年已经成为 Rust Web 开发的第一选择。它的 <code>tower::Service</code> 设计让中间件链非常优雅：</p>
<pre><code class="language-rust">use axum::{

use serde::Serialize;

#[derive(Serialize)]

    version: String,

    db: sqlx::PgPool,
}

    State(state): State&lt;AppState&gt;,

    // 检查数据库连接
    sqlx::query(&quot;SELECT 1&quot;).execute(&amp;state.db).await.unwrap();
    Json(HealthResponse {
        status: &quot;ok&quot;.into(),
        version: env!(&quot;CARGO_PKG_VERSION&quot;).into(),

        .route(&quot;/health&quot;, get(health_check))

<h3>数据库生态</h3>
<p>2026 年的 Rust 数据库生态不再是短板：</p>
<pre><code class="language-rust">use sqlx::postgres::PgPoolOptions;
use serde::{Serialize, Deserialize};

#[derive(Debug, Serialize, Deserialize, sqlx::FromRow)]
struct User {
    id: i64,
    name: String,
    email: String,
}

async fn get_user(pool: &amp;PgPool, user_id: i64) -&gt; Result&lt;User, sqlx::Error&gt; {
    sqlx::query_as::&lt;_, User&gt;(
        &quot;SELECT id, name, email FROM users WHERE id = $1&quot;
    )
    .bind(user_id)
    .fetch_one(pool)
    .await
}

async fn create_user(pool: &amp;PgPool, name: &amp;str, email: &amp;str) -&gt; Result&lt;User, sqlx::Error&gt; {
    sqlx::query_as::&lt;_, User&gt;(
        &quot;INSERT INTO users (name, email) VALUES ($1, $2) RETURNING id, name, email&quot;
    )
    .bind(name)
    .bind(email)
    .fetch_one(pool)
    .await
}
</code></pre>
<p>sqlx 已经支持 PostgreSQL 18 的 MERGE、增量物化视图等原生特性。Sea-ORM 在 ORM 层面也变得更加成熟。</p>
<h3>Cargo 生态里程碑</h3>
<p>crates.io 在 2026 年 7 月拥有超过 18 万个包。虽然远不及 npm 的 300 万，但 Rust 社区的哲学是「少而精」——很多功能可以直接内联编码，而不是依赖第三方包。</p>
<p>Cargo 的重要更新：</p>
<pre><code class="language-bash"># Cargo Script：直接运行 .rs 文件
cargo script run.rs

# PGO 原生支持（在 Cargo.toml 中）
# [profile.release]
# pgo = true

# Workspace 并行处理改进
cargo test --workspace --parallel
</code></pre>
<p>Workspace 的依赖解析和并行测试速度提升显著，大型 monorepo 的体验好了很多。</p>
<h2>AI 与 Rust 的交叉</h2>
<p>2026 年，AI 和 Rust 的关系在两个方向上深化。</p>
<h3>Rust 作为 AI 推理运行时</h3>
<p>随着端侧 AI 和边缘计算的爆发，Rust 在模型推理环节找到了独特定位：</p>
<pre><code class="language-rust">use candle_core::{Device, Tensor};

// 加载 ONNX 模型并进行推理
fn run_inference(model_bytes: &amp;[u8], input: &amp;[f32]) -&gt; Result&lt;Vec&lt;f32&gt;, Box&lt;dyn Error&gt;&gt; {
    let device = Device::Cpu;
    let model = candle_nn::ops::load_onnx(model_bytes, &amp;device)?;
    let input_tensor = Tensor::from_slice(input, (1, input.len()), &amp;device)?;
    let output = model.forward(&amp;input_tensor)?;
    Ok(output.to_vec1()?)
}
</code></pre>
<p>Candle（纯 Rust ML 框架）和 Burn 让 Rust 在 ML 场景下有了自己的话语权。特别是 Candle，性能接近 PyTorch 但不需要 Python 运行时。</p>
<h3>AI 辅助 Rust 开发</h3>
<p>2026 年的 AI 代码工具对 Rust 的支持达到可用水平：</p>
<pre><code class="language-rust">// 提示：实现一个线程安全的 LRU Cache
// AI 生成代码（2026 年水平）：
use std::collections::HashMap;
use std::sync::{Arc, Mutex};

struct LruCache&lt;K, V&gt; {
    inner: Arc&lt;Mutex&lt;Inner&lt;K, V&gt;&gt;&gt;,
}

struct Inner&lt;K, V&gt; {
    map: HashMap&lt;K, V&gt;,
    order: Vec&lt;K&gt;,
    capacity: usize,
}

impl&lt;K: Eq + Hash + Clone, V: Clone&gt; LruCache&lt;K, V&gt; {
    fn new(capacity: usize) -&gt; Self {
        Self {
            inner: Arc::new(Mutex::new(Inner {
                map: HashMap::new(),
                order: Vec::with_capacity(capacity),
                capacity,
            })),
        }
    }
    // ... get, put 实现
}
</code></pre>
<p>Rust 的类型系统其实比动态语言更适合 AI 代码生成——类型提供了天然约束，减少了生成结果的不确定性。</p>
<h2>行业落地案例</h2>
<p>说点具体的——2026 年谁在用 Rust 做什么。</p>
<h3>系统和网络层</h3>
<p>Linux 内核中的 Rust 支持已进入第 3 年。2026 年，已有超过 30 个内核模块使用 Rust：</p>

<h3>嵌入式与 IoT</h3>
<p>Rust 在嵌入式领域的进展同样迅猛：</p>
<pre><code class="language-rust">// 使用 embassy 的嵌入式 Rust
#![no_std]
#![no_main]

use embassy_executor::Spawner;
use embassy_time::{Timer, Duration};
use esp32c3_hal::gpio::{Level, Output};

#[embassy_executor::main]
async fn main(_spawner: Spawner) {
    let peripherals = esp32c3_hal::take().unwrap();
    let mut led = Output::new(peripherals.pins.gpio8, Level::Low);

    loop {
        led.set_high();
        Timer::after(Duration::from_millis(500)).await;
        led.set_low();
        Timer::after(Duration::from_millis(500)).await;
    }
}
</code></pre>
<p>embassy 框架让嵌入式异步编程变得直观，且 <code>#![no_std]</code> 特性意味着它可以在最小只有 64KB RAM 的设备上运行。</p>
<h2>Rust 的挑战</h2>
<p>客观地说，Rust 进前十并不代表它没有短板。</p>
<h3>学习曲线的现实</h3>
<p>借用检查器虽然有了更好的错误提示，但仍然不够友好：</p>
<pre><code class="language-rust">// 一个典型的借用检查器困惑
struct Container {
    items: Vec&lt;String&gt;,
}

impl Container {
    fn get_first(&amp;mut self) -&gt; &amp;str {
        // 编译错误：不能在可变引用后返回不可变引用
        self.items.push(&quot;new&quot;.into());  // 可变借用
        &amp;self.items[0]                  // 不可变借用，相互冲突
    }
}
</code></pre>
<p>异步编程的认知负载也比其他语言高很多。除了生命周期和所有权，你还要考虑 Send、Sync、<code>'static</code> 和 task 取消的安全性。</p>
<h3>编译速度的差距</h3>
<p>虽然 2026 年改善了，但和 Go、Java 的差距依然明显：</p>
<ul>
<li>Go：clean build 中型项目约 10 秒</li>
<li>Java（带 Gradle 缓存）：约 20 秒</li>
<li>Rust：clean build 中型项目约 3 分钟</li>
</ul>
<p>增量编译下差距缩小，但第一次构建的体验始终不如人意。</p>
<h3>就业市场的结构性差异</h3>
<p>TIOBE 前十会带来更多招聘需求，但 Rust 岗位分布很不均匀：</p>
<ul>
<li>基础设施公司（云原生、数据库、CDN）：大量需求</li>
<li>金融科技和量化交易：增长迅速</li>
<li>一般业务开发：几乎不招</li>
</ul>
<p>Rust 更像是 C++ 的继任者，而不是 Python/Java 的替代者。</p>
<h2>未来展望</h2>
<p>站在 2026 年 7 月，Rust 的未来有几个清晰的方向：</p>
<p><strong>进入前八只是时间问题</strong>。Android 和 Chrome 中的 Rust 代码量还在增长，一旦这些平台的 Rust 使用率达到某个阈值，TIOBE 排名会再上一个台阶。</p>
<p><strong>AI 辅助将降低门槛</strong>。2026 年 AI 代码工具对 Rust 的支持已经很好。Rust 的严格类型系统对 AI 来说其实是利大于弊——编译器可以验证 AI 生成的代码是否安全，减少了幻觉带来的问题。</p>
<p><strong>边缘计算是增量市场</strong>。Serverless WASM 市场年增速超过 60%，Rust 在这个领域几乎没有真正的竞争对手。</p>
<p><strong>更多「大龄」项目会考虑 Rust</strong>。随着越来越多 C/C++ 核心库的维护者退休或转向，安全性和可维护性将成为替换决策的主导因素，而这恰恰是 Rust 的优势区。</p>
<h2>结语</h2>
<p>回到最初的问题：Rust 凭什么杀进 TIOBE 前十？</p>
<p>不是靠炒作，不是靠杀手级应用。是<strong>十一年如一日在正确的时间做正确的事</strong>——内存安全、零成本抽象、没有 GC 的开销、对 LLVM 和 WASM 的优秀支持。这些特质在 2015 年是「异类」，在 2026 年是「先见之明」。</p>
<p>另一个角度：Rust 的增长几乎是「被动的」——不是开发者主动选择了它，而是行业依赖的基础设施正在用 Rust 重写。当一个 CDN 节点、一个数据库、一个内核都在用 Rust 时，工程师自然会被动或主动地接触到它。</p>
<p>这就是它进前十的真正原因。</p>
